Projet personnel · Python · PyTorch

Redonner une couleur plausible au gris.

Un modèle de deep learning transforme des images en niveaux de gris en colorisations cohérentes. Le projet couvre le pipeline de données, l’architecture, l’entraînement, l’inférence et l’évaluation.

Un même exemple, trois lectures.

Le pipeline

Les images passent dans l’espace CIELAB. Le modèle reçoit la luminance L et prédit les canaux chromatiques a et b. Un U-Net léger, enrichi par une attention CBAM, reconstruit ensuite l’image colorisée.

Mesurer avant de montrer

Les résultats ci-dessous viennent d’une évaluation indépendante sur 100 images de test, sélectionnées avec la seed 42.

23,29PSNR moyen
0,940SSIM moyen
14,84DeltaE moyen

Les couleurs sont plausibles, mais une image noir et blanc ne permet pas de garantir les couleurs historiques d’origine.

Projet personnel · Python · IA locale

Comprendre un RAG en le construisant.

Un assistant local répond à des questions sur un PDF en recherchant les passages utiles avant de solliciter un modèle GGUF. Le projet m’a surtout appris à transformer les principes d’un RAG en un pipeline Python compréhensible.

Une question, une réponse locale, une source vérifiable.

Le flux RAG

Chaque étape est visible dans le code : le document est extrait, découpé, vectorisé puis recherché. Les passages sélectionnés sont formatés dans un contexte avant l’appel au modèle local.

  1. Extraire les pages du PDF avec PyMuPDF.
  2. Découper le texte avec une taille et un chevauchement contrôlés.
  3. Créer les embeddings et les conserver dans ChromaDB.
  4. Rechercher les candidats puis appliquer une sélection MMR.
  5. Construire le prompt et générer une réponse sourcée avec llama.cpp.

Le travail réalisé

Je n’ai pas importé une solution RAG complète. J’ai étudié le fonctionnement du retrieval augmented generation, puis écrit l’orchestration qui relie extraction, chunking, embeddings, recherche, contexte et génération.

Stack : Python · FastAPI · PyMuPDF · ChromaDB · sentence-transformers · llama.cpp · GGUF · CUDA · HTML/JavaScript.

Les bibliothèques spécialisées restent utilisées pour leurs responsabilités propres ; la logique du pipeline et son enchaînement sont codés dans le projet.

Architecture locale

Le navigateur appelle FastAPI. L’API lit le document, interroge ChromaDB et envoie le contexte à llama.cpp, sans service distant.

Limites honnêtes

Ce POC est conçu pour un usage local : il ne fournit pas d’authentification, dépend d’un modèle GGUF obtenu séparément et n’est pas destiné à être exposé directement sur Internet. La qualité dépend du document, du modèle et des réglages de génération.

Local Second Brain.

Un système en développement pour transformer des contenus provenant de sources variées en notes enrichies, reliées et consultables dans un espace de connaissances local.

Projet en développement · dépôt GitHub non public

Un graphe de connaissances local, présenté avec des données anonymisées.

Le principe

Local Second Brain explore une idée simple : faire passer des contenus hétérogènes par un pipeline local, puis les transformer en connaissances structurées. Le projet peut accueillir des liens, des vidéos ou d’autres sources sans dépendre d’un format unique.

CollecterSynchroniser des contenus et conserver leur contexte.
EnrichirTranscrire, analyser et ajouter des métadonnées utiles.
RelierConstruire des liens entre notes, concepts et projets.
ExplorerRetrouver les idées dans une interface locale et un graphe.

Architecture

Le schéma distingue les sources, le pilotage local, le pipeline de jobs, l’enrichissement et la base de connaissances Obsidian.

Ouvrir le schéma interactif

Ce que je construis

Les fonctionnalités principales sont la synchronisation de contenu, l’enrichissement automatique, un serveur MCP à accès contrôlé, une interface FastAPI/React et la génération de liens vers Obsidian.

  1. Recevoir un contenu depuis une source variée
  2. Le traiter dans une file de jobs locale
  3. Ajouter transcription, analyse et métadonnées
  4. Créer ou mettre à jour une note structurée
  5. Relier la note au reste du graphe de connaissances

Ce que j’ai appris

Ce projet m’a appris à automatiser un navigateur, traiter des contenus multimédias, gérer un pipeline de jobs, concevoir des accès MCP limités et construire progressivement un système de connaissances personnel.

Le projet reste expérimental : certaines intégrations évoluent encore et la démonstration publique utilise uniquement des données fictives ou anonymisées.

Projet personnel · Flutter · Supabase

Photographier un repas, puis corriger l’estimation.

WarungFit est une application mobile qui estime les apports d’un repas à partir d’une photo. L’utilisateur peut corriger le résultat, enregistrer son repas et suivre ses objectifs dans le temps.

Étude de cas · code source privé

Le parcours

WarungFit place une étape de correction entre la réponse du modèle et l’ajout du repas à l’historique.

  1. Prendre une photo ou choisir une image
  2. Envoyer l’image à une fonction serveur authentifiée
  3. Recevoir une estimation structurée du repas
  4. Corriger les ingrédients et les portions proposés
  5. Enregistrer le résultat dans l’historique

Ce que j’ai construit
